# Generic task playbook

## Generic playbook

- Entry and design: narrow affected seam and ordinary obligations.
- Phase steps: task-specific checks at existing discovery/design/affected-path verification seams.
- Skip reasons: no route controls: omit specialized duties; retain fixed stages, Gates, required verification, authority.
- Red or pin: existing task-appropriate Red or pin.
- Delivery proof: existing affected-path delivery verification.

### Conditional Principles

- **Change sizing:** read [subtract-before-add](../../principles/subtract-before-add.md#subtract-before-adding) only when observed; otherwise skip the leaf.

### Procedure

1. [Discovery](../stages/discovery.md#procedure): Collect facts and define the narrow affected outcome without guessing a specialized route.
2. [Design](../stages/design.md#procedure): Resolve load-bearing decisions and choose a proportionate design.
3. [Planning](../stages/planning.md#procedure): Record acceptance, dependencies and verification seams.
4. [Implementation](../stages/implementation.md#procedure): Use the task-appropriate Red or pin and independently verify changes.
5. [Delivery](../stages/delivery.md#procedure): Verify the actual affected outcome and fresh full evidence.
