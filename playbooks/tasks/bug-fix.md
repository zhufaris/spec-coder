# Bug Fix task playbook

## Bug Fix playbook

- Entry and design: reproduced symptom and root cause on matching surface.
- Phase steps: reproduction/root-cause evidence at existing discovery/design/affected-path verification seams.
- Skip reasons: defect controls: omit new-outcome/baseline duties; retain fixed stages, Gates, verification, authority.
- Red or pin: failing reported-defect reproduction.
- Delivery proof: reproduction green; neighboring behavior covered.

### Conditional Principles

- **Change sizing:** read [subtract-before-add](../../principles/subtract-before-add.md#subtract-before-adding) only when observed; otherwise skip the leaf.

### Procedure

1. [Discovery](../stages/discovery.md#procedure): Capture and reproduce the exact reported entry path; locate the first incorrect behavior.
2. [Design](../stages/design.md#procedure): Choose the smallest root-cause repair; clarify only missing load-bearing facts.
3. [Planning](../stages/planning.md#procedure): Carry the original reproduction identity into task acceptance and proof.
4. [Implementation](../stages/implementation.md#procedure): Observe reproduction Red, repair minimally, cover neighboring behavior.
5. [Delivery](../stages/delivery.md#procedure): Rerun the original public path on integrated code; generic Green cannot replace it.

### Completion

The task owns step order and route-specific proof; stage playbooks own local actions. Preserve the fixed stages and approval contracts. A failing step returns to its stage owner; an invalid design returns to design. Record an explicit skip reason only for inapplicable task-specific work. No step grants external effects or nested delegation.
